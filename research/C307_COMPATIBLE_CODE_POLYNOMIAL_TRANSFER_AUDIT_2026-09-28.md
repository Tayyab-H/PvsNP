# C-307 - AND-count separators compile to native covers; arithmetic code bounds do not transfer automatically

Date: 28 September 2026  
Classification: **EXACT MODEL BRIDGE / ALGEBRAIC ROUTE FILTER.** The compiler is proved with one fusion pair per AND gate. It sharpens the separator-to-cover resource accounting but does not improve the actual Gap-MCSP exponent. A code-polynomial lower bound over the ordinary arithmetic semiring is not a lower bound for compatible-support fusion.

## 1. The resource to isolate

Let Y,Z be disjoint subsets of {0,1}^N, and encode a complete table w by its 2N matching signed literals e(w). Assume every signed literal half-cube meets Z, as holds for the OPS high set because |SIZE(s2)|=2^{o(N)}<2^{N-1}.

Define A_cap(Y,Z) as the minimum number of binary AND gates in an acyclic monotone circuit on the signed-literal inputs that accepts every e(w), w in Y, and rejects every e(z), z in Z. OR gates have arbitrary fan-in and are free in this measure.

## 2. One pair per AND gate

Take a circuit witnessing A_cap(Y,Z)=a. Flatten every OR-only path: each input to an AND gate is an OR of signed literals and earlier AND-gate outputs. Topologically order the AND gates as g_1,...,g_a.

For every signal v, let
\[
T_v=\{z\in Z:v(e(z))=1\}.
\]
If g_i=L_i AND R_i, where L_i and R_i are the flattened ORs of terms, set
\[
E_i=\bigcup_{u\text{ a term of }L_i}T_u,\qquad
H_i=\bigcup_{v\text{ a term of }R_i}T_v.
\]
Then E_i intersect H_i=T_{g_i}. Use (E_i,H_i) as one fusion pair.

Fix w in Y. Inductively, every circuit signal true on e(w) has its carrier in the upward closure generated by the matching literal slices, unless an empty carrier has already been derived. A true literal contributes its matching seed slice. A true OR has a true term whose carrier is contained in the OR carrier, so upward closure adds the latter. If an AND gate is true, both endpoint carriers are present, and its pair derives their intersection T_{g_i}.

Soundness on high anchors is immediate from the principal semi-filter at z: it contains every set containing z and preserves every pair, since if both endpoints contain z then their intersection does too. Thus no pair list can derive the empty set on a high anchor.

The output of a separator cannot have a direct literal term: every literal half-cube contains a point of Z, and a true output literal would accept that high point. Thus each low input makes some output AND signal true. Its carrier is empty because the separator rejects every point of Z. The corresponding pair list derives the empty set on every w in Y. Therefore
\[
\boxed{\rho_{\mathrm{prom}}(Y,Z)\le A_{\cap}(Y,Z).}
\]
This proof uses arbitrary semantic endpoints in Z, as allowed by the native cover model. It does not charge OR fan-in or duplicate AND fan-out.

The reverse resource inequality already in the project is the acyclic unrolling A_cap(Y,Z)<=rho_prom(Y,Z)^2. Together:
\[
\boxed{\sqrt{A_{\cap}(Y,Z)}\le \rho_{\mathrm{prom}}(Y,Z)\le A_{\cap}(Y,Z).}
\]
The sharper right-hand side improves the prior total-gate separator compiler when OR routing is large. It does not remove the quadratic loss in the direction needed to infer a fusion lower bound from an acyclic lower bound. To force rho_prom>N^{1+epsilon} through this route, it still suffices to prove A_cap>N^{2+2epsilon}.

## 3. Corollary: sparse local constraints have linear native covers

Suppose a Boolean promise has YES set C subseteq {0,1}^N, and C is exactly the satisfying set of local constraints R_t on coordinate sets S_t, with |S_t|<=d. For each forbidden local pattern a not in R_t, make the monotone signed-literal clause
\[
\bigvee_{j\in S_t}[x_j\ne a_j].
\]
The conjunction of these clauses accepts exactly C on complete tables. If
\[
M=\sum_t (2^{|S_t|}-|R_t|),
\]
the separator uses at most M-1 binary AND gates, hence the native cover uses at most M-1 pairs (assuming every literal slice meets the NO set). In particular, bounded-arity constraint systems with O(N) forbidden local patterns have O(N)-pair covers, regardless of how many YES codewords they contain.

This is a source-selection warning: code rate, distance, and a large number of codewords do not by themselves create native complexity. A proposed hard code source must also rule out a short signed local-constraint separator, or show why the local-constraint separator fails the required C-125/OPS transfer.

## 3.1 Expander-code calibration: exponentially many full certificates with linear q

Sipser-Spielman expander codes give an asymptotically good binary LDPC family: the code has positive rate and relative distance, and its parity checks have bounded weight. Fix a family C⊆{0,1}^N with dimension ρN for constant ρ>0, minimum distance at least δN for constant δ>0, and O(N) checks of constant weight. The source paper describes expander codes as asymptotically good linear codes in the LDPC class: https://www.cs.yale.edu/homes/spielman/PAPERS/expandersIT.pdf

Treat Y=C and Z={0,1}^N\C. Each parity check has at most 2^d forbidden local patterns for a fixed constant d. The signed-clause construction above therefore gives a separator with O(N) AND gates and a native cover with q=O(N). Every literal half-cube meets Z: its size is 2^{N-1}, while |C|=2^{ρN}<2^{N-1} for large N.

Yet every sound output proof support matching a codeword must be complete. Soundness says its completion cylinder contains no point of Z, hence lies wholly in C. If the support leaves any coordinate free, its cylinder contains two tables at Hamming distance one, impossible in a code with minimum distance at least two. Therefore the cover accepts 2^{ρN} distinct full-table supports using O(N) rules.

This is a direct stress test for owner-mask and certificate-count arguments: even an exponentially large family of isolated, far-apart full certificates can be generated by a linear-size native grammar. The code promise is only a calibration; its codewords are not shown to all lie in SIZE(s1), so this is not an OPS reduction or a P-vs-NP result. The next invariant must measure how the grammar generates compatible alternatives, not count its output supports or invoke code distance alone. Primary source: [Sipser-Spielman, Expander Codes](https://www.cs.yale.edu/homes/spielman/PAPERS/expandersIT.pdf)

## 4. OPS-specific lower bound for direct monotone CNFs

The code calibration says sparse constraints are easy; for the actual OPS promise, however, a separator that is itself a conjunction of signed-literal clauses needs superpolynomially many clauses.

Let h be a monotone CNF on the 2N signed table literals, equal to 1 on SIZE(s1) and 0 outside SIZE(s2). After removing tautological clauses and duplicate literals, a clause of width k is falsified by one partial assignment on k distinct table coordinates. Every assignment to at most
\[
K=\left\lfloor\frac{s_1}{4n}\right\rfloor,\qquad n=\log_2N,
\]
coordinates has a low-circuit completion: set all unspecified table bits to 0 and compute the at most K specified 1-entries as a DNF of address minterms. A direct circuit for that table uses at most 3Kn<=s1 gates for sufficiently large n. Therefore no clause falsified by a pattern on at most K coordinates can occur in h, since that falsifying subcube contains a low table.

Every remaining clause has width at least K+1, so a uniformly random N-bit table falsifies it with probability at most 2^{-(K+1)}. The high set occupies 1-o(1) of the cube because |SIZE(s2)|=2^{o(N)}. Since every high table must falsify at least one clause, the union bound forces
\[
m\ge(1-o(1))\,2^{K+1}
=2^{\Omega(s_1/n)}
=2^{\Omega(N^\beta/(\log N)^2)}
\]
clauses. This is superpolynomial in N for every fixed beta>0.

This proves a strong route-specific result: a direct local-clause/CNF separator cannot yield the desired near-linear cover for OPS. It is not a lower bound for general monotone circuits or native q-state closures. Sharing AND subexpressions can create exponentially many implicit clauses, and no conversion preserving q is known. The active mechanism must therefore use genuinely shared intermediate intersections or a global selector; merely listing forbidden partial patterns is ruled out.
## 5. Why the ordinary arithmetic-code lower bound is not a native lower bound

Cavalar, Kumar, and Rossman define the code polynomial
\[
P_C=\sum_{c\in C}\prod_{j=1}^m x_{c_j,j}
\]
and prove that if distinct codewords agree on at most m/3-1 coordinates, then every monotone real arithmetic circuit computing P_C has size at least |C|. The proof uses a homogeneous decomposition into sums of products and the fact that every nonzero positive-coefficient cross-product survives in the output polynomial. [Primary paper, Theorem 4.4](https://eccc.weizmann.ac.il/report/2020/181/revision/2/download/)

The C-281 support algebra has different multiplication:
\[
m_Sm_T=0\quad\text{when }S,T\text{ conflict}.
\]
It is also idempotent on alternatives: repeated supports collapse. Consequently, mixed products that are present in the arithmetic proof can disappear natively as conflicts. For example, a left family containing supports {1=0},{1=1} and a right family containing {1=0,2=0},{1=1,2=1} has only the two diagonal compatible unions; both mixed unions are zero. This is exactly a consistency filter, not cancellation. Therefore Theorem 4.4 cannot be imported without a new lower bound for compatible products.

There is a second gap: the theorem is for a polynomial indexed by a code over a constant-size alphabet; it does not provide a C-125 map from that code problem into OPS truth tables with s1=N^beta/(c log N), high completions outside SIZE(s2), and a positive decision/reconstruction margin.

## 6. Disposition and checkpoint

**Proved:** an acyclic separator with a binary AND gates yields a native cover with at most a pairs under the dense-high-slice condition; sparse local constraint promises have the stated linear cover.

**Not proved:** a superquadratic AND-count separator lower bound for the OPS promise, a compatible-product lower bound for any explicit code source, a near-linear full-promise OPS cover, or any change to the actual rho_GapMCSP=N-o(N) lower bound.

The next algebraic target is not raw code distance, direct CNF size, or ordinary arithmetic circuit size. It is a q-sensitive bound for the recursive compatible-product grammar that accounts for conflict filtering and global description synchronization, while passing C-257 parity and C-258 equality. The active construction target remains a sound near-linear full-promise cover or a state-level global selector; C-306 has ruled out support tags as that selector.
